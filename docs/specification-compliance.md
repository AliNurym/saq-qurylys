# Текущий статус — 20 октября 2026

Текущая цель — **«Кейс Codemasters 8.0. SAQ.pdf»**, то есть хакатонный MVP. Подробный DOCX описывает отдельный промышленный пилот и не используется как критерий этого кейса. После изменения формулы и полировки полный набор прошёл: 301/301 тест; build/lint прошли для 109 JavaScript-файлов. Точность учебной модели на реальных данных не измерялась. Подробности по пилоту DOCX и его незакрытым данным: [анализ ТЗ от 20 октября](tz-gap-analysis-2026-10-20.md).

В приложениях и протоколах импорта, созданных по прежней пилотной модели, встречается `yellow` при 0 баллов. Это историческая метка; по текущим порогам PDF 0 баллов — зелёная числовая зона, а неизвестность остаётся отдельным `needsReview`.

Воспроизведена и исправлена запись по отозванному доступу после ожидания чужого писателя SQLite: право/сеанс повторно проверяются под блокировкой до изменений. Версия настроек, статус фактора и допустимость перехода сигнала также проверяются в транзакции. Есть HTTP-регрессии с двумя процессами; системные задания работают от System. [Конкретная граница проверки](transaction-consistency.md).

Правовое решение обязательно связано с версией карточки. Изменение значимых реквизитов участка/компании/документов после подтверждения переводит основание на повторную проверку и снимает прежнее подтверждение R1; исходные доказательства, аудит и снимки сигналов сохраняются. Повторное решение МИО требует актуальной версии. Это прикладная защита актуальности, не юридическая проверка документа или интеграция с реестром. [Правила и проверки](transaction-consistency.md).

Обращения теперь можно регистрировать и проверять в рабочем процессе: нулевой балл до решения МИО, подтверждённое коллективное → R4, неизменяемый приём/журнал, разрешение/отзыв без удаления, снимок в сигнале/HTML. Связанный R4 нельзя менять в обход решения; другие активные обращения продолжают учитываться. Реальный внешний сервис обращений не подключён. [Контракт](complaints.md).

Последнее исправление правил: положительного основания больше недостаточно для green. Нужны явные решения МИО по связи документов с объектом, фактическому строительству, существенным жалобам и просрочке с источником/датой. Проверка связана с контекстом и имеет записанное 30-дневное окно повторной проверки — это правило приложения, не срок разрешения. Старые положительные сведения не достраиваются миграцией; исторические сигналы сохранены. [Контракт](object-conditions.md).

Последний этап: [очередь реагирования](signal-inbox.md) показывает получателя, срок, просрочку и результат; фильтры/поиск/страницы и счётчики учитывают права до подсчёта. МИО не может архивировать назначенный материал без ответа получателя. Старый архив не переписывается. Списки/обзор передают краткие записи, полный набор доказательств остаётся в отдельной карточке и экспорте. Цепочка ГАСК → результат → архив МИО проверена в браузере на изолированных синтетических данных.

## Матрица требований отдельного DOCX-пилота

## Итог по шести критериям приёмки §7

Для подготовки реальных данных проверен публичный каталог Homeportal: городской запрос вернул 10 записей; сохранено происхождение каждой, подготовлен CSV из 8 кандидатов, 2 отложены из-за координат. Штатный импорт проверен только в базе в памяти; основная база не изменялась. Все 8 остаются непроверенными, `UNKNOWN`, yellow, 0 баллов. Полный состав 48 ЖК этим не установлен. [Источники, проверка и ограничения](public-registry-intake.md).

1. **48 паспортов:** не выполнено.
2. **Зона с расшифровкой для каждого объекта:** локальная функция работает; по всем реальным 48 объектам не подтверждено.
3. **Ежедневная реклама всех источников со снимками:** частично, полного покрытия и автоматических скриншотов нет.
4. **Все красные карточки со всеми разделами:** локальный процесс работает; полнота материалов реального пилота не подтверждена.
5. **Нет неподтверждённой внешней передачи, есть аудит:** приложение не отправляет материалы наружу; локальная верификация/маршрутизация/аудит проверены. Интеграционная передача не реализована.
6. **Сотрудники обучены и работают:** не выполнено.

**Промышленный пилот не принят.** Следующие внешние зависимости: подтверждённый реестр 48 объектов и документы, доступ к источникам/госреестрам, сервер/эксплуатация в РК и участие сотрудников МИО. Автоматическую оценку готовности и качество ИИ нужно отдельно валидировать на независимых реальных данных. Сравнение с Claude требует общего независимого набора, результатов второй реализации здесь нет.

## История предшествующих этапов

Последний этап: HTTPS-прокси с фиксированным origin, доверенным адресом клиента, защищёнными cookies и запретом публичного запуска без ADMIN; согласованные копии SQLite и восстановление в новый файл с проверкой сохранности материалов и отключением старого доступа/очереди. **175/175 тестов**, build/lint для 83 JS-файлов. Это подготовка эксплуатации; хостинг в РК, доверенный публичный TLS, 48 реальных объектов, нативные API и обучение остаются незавершёнными. Инструкции: [HTTPS](deployment.md), [копирование/восстановление](backup-recovery.md). Далее — хронология предыдущих этапов и основная матрица требований.
