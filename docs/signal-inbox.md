# Очередь сигналов и контроль реагирования

## Интерфейс

Раздел «Сигналы» показывает номер, сохранённое название ЖК/город, балл/зону, статус, орган-получатель, дату ответа и состояние реагирования. Доступны поиск по номеру/объекту/городу, фильтры статуса/получателя/результата, порядок по времени либо сроку и переход к следующим материалам. На мобильном экране строки перестраиваются без горизонтального переполнения страницы.

Счётчики относятся **ко всем материалам, доступным текущему пользователю**, независимо от выбранных фильтров. Нажатие на счётчик открывает соответствующую полную выборку. «Ожидают ответа» включает просроченные. Срок сегодня ещё не просрочен; календарная дата оценивается в Asia/Qyzylorda. При сортировке по сроку сначала идут просроченные, затем ожидающие ответа, неназначенные, завершённые и архив. Сам срок уже рассчитан и заморожен при назначении; список его заново не пересчитывает.

ГАСК/правоохранительный орган видит только назначенные этому органу CONFIRMED/ARCHIVED карточки. Подсчёты, поиск, фильтры и курсоры применяют ту же границу доступа. Даже если другой орган имеет материалы по тому же ЖК, его карточки в этот список не входят. МИО/ADMIN видит общую очередь согласно существующим полномочиям; изменять материал и вносить результат можно только по серверным правилам роли.

## Краткий HTTP-контракт

`GET /api/signals` возвращает краткие записи и сведения о странице:

- `items`: номер/ЖК/город, балл/зона, статус, автор/время, краткий `routing` (получатель, назначение, срок, время результата), `hasResponse`, `responseState`, `overdue`.
- `total`: число записей, соответствующих выбранным фильтрам, без ограничения курсором.
- `limit`, `nextCursor`, нормализованные `filters`.
- `summary`: все видимые материалы (`total`), требующие работы МИО (`review`), NEEDS_REVIEW (`needsReview`), ожидающие/просроченные/с результатом. `summaryScope=ALL_VISIBLE_SIGNALS`.
- `evaluationDate`: дата определения просрочки; `checkedAt`: фактическое время запроса.

Параметры:

| Параметр | Значения |
| --- | --- |
| status | DRAFT, NEEDS_REVIEW, CONFIRMED, RETURNED, ARCHIVED либо пусто |
| recipient | MIO, GASK, LAW_ENFORCEMENT либо пусто |
| response | UNASSIGNED, AWAITING, OVERDUE, RESPONDED, ARCHIVED либо пусто |
| sort | newest (по умолчанию), deadline |
| search | До 200 символов; буквальный поиск без учёта регистра, включая кириллицу |
| complexId | Ограничение конкретным ЖК, не расширяет доступ |
| limit | 1–100, по умолчанию 20; интерфейс использует 20 |
| before | `nextCursor` предыдущего ответа при тех же фильтрах и правах |

AWAITING включает активные просроченные карточки. RESPONDED включает и архивные карточки с результатом. ARCHIVED показывает весь архив, в том числе сохранённые старые карточки без результата. Состояние записи такого старого материала — «Архив без результата»; активной просрочкой он не считается.

При одинаковой дате используются внутренний порядок SQLite rowid и составной курсор: совпадение времени не теряет записи. Курсор привязан к фильтрам, сортировке и границе доступа. Некорректный/чужой курсор — 400; после смены календарного дня — 409 с предложением обновить список. Курсор служит навигации и не является токеном доступа или гарантией неизменности живой очереди между запросами. После смены прав, даты или фильтров следует открыть первую страницу.

## Доказательства и объём ответа

Краткий список, bootstrap-обзор и список сигналов в ЖК больше не передают `contextSnapshot`, `factorSnapshot`, изображения base64 и полное определение календаря. Сохранённые название и город извлекаются из исходного снимка, поэтому последующая правка паспорта их не заменяет. Для legacy-сигнала без снимка используется доступная подпись объекта и сохраняется признак legacy.

Полный `GET /api/signals/:id` и автономный `/:id/export` сохраняют доказательства, фото, архивные тексты, паспорт, факторы, календарь и аудит. Изменение касается представления списка, сами строки сигналов не переписываются. Клиентам, которые раньше брали полные снимки из списка, нужно читать отдельную карточку.

## Завершение и архив

Назначенная карточка без результата получателя не архивируется: сервер возвращает 409, интерфейс не показывает действие архива и объясняет порядок. МИО не может внести ответ за ГАСК или правоохранительный орган. После записи результата назначенным получателем МИО может архивировать карточку; результат/автор/время сохраняются. Повторная запись результата запрещена прежними правилами и триггерами. Старые архивные карточки автоматически не меняются и не открываются заново.

Карточка без назначения не создаёт обязательства получателя и может архивироваться по прежним переходам статуса. Внешняя ведомственная отправка, email/SMS и промышленное SLA здесь не реализованы.

## Проверка

`test/signal-inbox.test.mjs`: серверные состояния сроков, курсоры с одинаковым временем, Unicode/буквальный поиск, снимок названия, изоляция получателя и счётчиков, смена суток, краткие ответы при сохранении полного detail, архивная защита и HTTP-цепочка ролей.

`test/signal-inbox-ui.test.mjs`: формы/подписи, навигация с фильтрами, экранирование, пустые состояния, RU/KZ, legacy-архив и отсутствие действия архива до результата.

Изолированный Edge/Playwright: 28 синтетических карточек, страницы/фильтры/RU-KZ, права ГАСК, ответ ГАСК → архив МИО, 1440/390/320 px. Список 28 кратких записей в фикстуре — 15 711 байт, одна полная карточка с искусственным дополнительным содержимым снимка — 36 837 байт. Это иллюстрация формы ответа на контролируемых данных, **не** замер промышленной производительности или реального объёма материалов.
