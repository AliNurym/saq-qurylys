# Автоматический сбор публикаций

Добавлен опциональный [статический браузерный снимок HTML-источника](page-capture.md): до 1280 × 12 500, связь с архивным HTML, без JavaScript и сетевых загрузок, неизменяемое изображение и экспорт в сигнал. Внешние стили, шрифты, изображения и динамический контент не загружаются; такие снимки помечаются PARTIAL. Нужны отдельно настроенные Playwright/Chromium; без них явно указан NOT_CONFIGURED. Это не полная страница и не полное покрытие рекламных платформ.

Бэкенд получает публикации из явно настроенных HTTPS-источников, сохраняет исходные ответы и передаёт текст в отдельную очередь анализа. Добавлены два адаптера: `HTML_PAGE` для одной публичной страницы и `JSON_FEED` для предоставленного API публикаций. Создание источника требует входа администратора, в том числе в демонстрационном режиме.

Автоматический сбор из нативных Instagram, TikTok и Telegram API пока не подключён. Для соцсетей можно настроить разрешённый оператором шлюз, который возвращает контракт ниже. Наличие этого адаптера не означает, что получены аккаунты, разрешения или данные конкретной платформы.

## Настройка источника через API

После входа администратора отправьте `POST /api/admin/sources`:

```json
{
  "name": "Публикации предоставленного источника",
  "kind": "JSON_FEED",
  "platform": "Telegram",
  "url": "https://example.com/saq-publications",
  "enabled": true,
  "intervalMinutes": 1440,
  "tokenEnv": "SAQ_SOURCE_PUBLICATIONS_TOKEN"
}
```

URL примера не предоставляет реальную ленту. `tokenEnv` необязателен: это имя переменной окружения процесса, содержащей Bearer-токен. Значение токена не передаётся в настройках и не возвращается в API источников. После изменения окружения процесс нужно перезапустить. Значения секретов не следует включать в URL.

`HTML_PAGE` использует тот же контракт настройки, но получает HTML по одному указанному URL. Он извлекает текст из `main`, `article` либо `body`, исключает скрипты, стили и HTML-комментарии. JavaScript страницы не исполняется. Навигация сайта и полноценное браузерное распознавание контента не реализованы: страницы с динамической загрузкой данных могут потребовать отдельного API.

## Формат JSON_FEED

```json
{
  "items": [
    {
      "id": "stable-provider-publication-id",
      "text": "Исходный полный текст публикации",
      "url": "https://example.com/publication/123",
      "account": "public_account",
      "phone": "+7 700 000 00 00",
      "publishedAt": "2026-10-01T09:00:00+05:00"
    }
  ]
}
```

Обязательны строковые `id` и `text`; `publishedAt`, `url`, `account`, `phone` необязательны. Ответ — UTF-8 JSON, до 2 МБ и до 100 публикаций за один опрос; текст — 5–12000 символов. Неполный или неоднозначный пакет отклоняется целиком. Пагинация, курсоры и частичная выборка требуют специализированного адаптера: этот контракт описывает полный ответ настроенной ленты в пределах лимита.

Если дата публикации неизвестна, сохраняется `publishedAt=null`. В существующем поле даты объявления хранится день наблюдения с явной заметкой; `collection.publishedAt` и печатный экспорт показывают отсутствие даты публикации. Время наблюдения хранится отдельно в UTC. Пропущенная дата не реконструируется из текущего времени как установленный факт публикации.

## Очередь и восстановление

- Включённый источник по умолчанию опрашивается раз в сутки. Интервал — 60–10080 минут; пропущенное расписание догоняется одним опросом после запуска.
- Задачи и расписание находятся в SQLite. Рабочий процесс проверяет пустую очередь раз в секунду и исполняет одну задачу за раз; после завершения сразу берёт следующую, не добавляя секунду задержки на каждую публикацию.
- Состояния: `PENDING`, `RUNNING`, `SUCCEEDED`, `FAILED`, `CANCELLED`. Задача получает аренду на 120 секунд с отдельным идентификатором владельца; после остановки её может забрать другой исполнитель. Потерявший аренду сборщик не может сохранить результаты.
- До четырёх попыток; задержки повторов начинаются с 30 секунд и увеличиваются вдвое. После исчерпания попыток доступен явный повтор администратором.
- Получение и анализ — отдельные задачи. Ошибка анализа не требует повторной загрузки и не удаляет сохранённую публикацию.
- Для пары `источник + внешний id + хеш содержимого` создаётся одна публикация. Изменённый текст с прежним внешним id сохраняется новой версией. Архив каждого успешного опроса сохраняется, включая опросы без новых публикаций.
- Запись публикаций, происхождения, очереди анализа и аудита выполняется одной транзакцией. Сбой записи откатывает весь пакет. Сетевые операции выполняются вне транзакций.
- Исполнение задач допускает повтор после аварии. Дедупликация предотвращает повторное создание одинаковой версии публикации; повторный анализ может создать дополнительную версию анализа и не подтверждает факторы автоматически.

Отключение источника отменяет ожидающие задачи сбора. Если конфигурация изменилась во время загрузки, старый ответ не попадает в реестр. Уже сохранённые материалы и их анализ остаются доступны.

## Архив и права

Сохраняются точные байты HTML/JSON, MIME, конечный URL после перенаправлений, время получения, SHA-256 и снимок настроек источника без токена. Триггеры SQLite запрещают изменение и удаление архива и происхождения публикации. Это исходный сетевой ответ, а не скриншот, не доверенная временная метка и не самостоятельно установленное юридическое доказательство.

`GET /api/ads/:id` возвращает `collection` с происхождением. `GET /api/ads/:id/archive` скачивает исходные байты с SHA-256 в заголовке; HTML отдаётся как вложение без исполнения. Получатели видят архив только в пределах назначенных им объектов. Новые сигналы фиксируют происхождение вместе с текстом; печатная выгрузка включает идентификатор и хеш архива. Исходный ответ скачивается отдельно.

Транспорт допускает HTTPS на порту 443, проверяет все DNS-адреса и закрепляет соединение за проверенным адресом. Локальные, частные и служебные сети, URL с паролями и небезопасные перенаправления отклоняются. Общий срок загрузки — 15 секунд; до трёх перенаправлений; Bearer-токен не передаётся на другой origin. Неизвестные форматы и сжатые ответы отклоняются.

База с настроенными источниками не может быть переименована из `demo` в `working` или сброшена демонстрационной командой. Для настоящих данных нужна отдельная рабочая база с администратором.

## Операционные маршруты

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | `/api/admin/sources` | Настроенные источники и ближайшие запуски |
| GET | `/api/admin/sources/:id` | Конфигурация, состояние переменной доступа, счётчики архивов/версий публикаций и последний сбор |
| POST | `/api/admin/sources` | Новый источник |
| PUT | `/api/admin/sources/:id` | Изменение с обязательным `expectedUpdatedAt` |
| POST | `/api/admin/sources/:id/run` | Поставить сбор в очередь; повторный запрос возвращает активную задачу; необязательный `expectedUpdatedAt` защищает от смены конфигурации |
| GET | `/api/admin/jobs` | Очередь с фильтрами и курсором, по умолчанию до 200 записей |
| GET | `/api/admin/jobs/:id` | Состояние, безопасный код ошибки, до 100 новых публикаций сбора и до 50 последних событий задачи |
| GET | `/api/admin/jobs/:id/archive` | Точные байты архива успешного сбора, в том числе при отсутствии новых публикаций |
| POST | `/api/admin/jobs/:id/retry` | Повтор завершившейся с ошибкой задачи |

Все операции управления доступны администратору; пароли, сессии и правила доступа используются из существующей системы авторизации.

`GET /api/admin/jobs` принимает `limit` 1–200, `before` (идентификатор последней задачи предыдущей страницы), `state`, `kind`, `sourceId`. Ответ: `items`, `total`, `nextCursor`, `checkedAt`. Фильтр источника включает и сбор, и анализ его сохранённых публикаций. История доступна после первых 200 задач. Состояния могут меняться между страницами: это оперативная очередь, а не замороженный снимок.

Конфигурация возвращает `tokenStatus`: `NOT_REQUIRED`, `MISSING` или `CONFIGURED`. Последнее означает наличие серверной переменной, но не проверку токена внешней платформой. Значение переменной не возвращается. Диагностика задач содержит код и известное локальное пояснение; неизвестные сообщения провайдера, включая ошибки с HTTP 400, не копируются в публичное поле. Старые задачи после миграции могут иметь `errorCode=null`; причина не восстанавливается задним числом.

### Управление через интерфейс

В «Настройки → Источники» администратор добавляет URL, тип ответа, название платформы, интервал и необязательное имя серверной переменной токена. Новый источник по умолчанию отключён; сохранение такого источника не запускает запрос. Включение разрешает автоматический сбор при работающем сервере. Настройка и перезапуск серверных переменных выполняются оператором на сервере; сам токен в форму не вводится.

«Поставить сбор в очередь» использует сохранённую конфигурацию. При несохранённых изменениях кнопка недоступна. Интерфейс также передаёт сохранённую версию, чтобы параллельная смена URL или доступа не стала незаметным запуском по другим настройкам. Конфликт предлагает загрузить актуальные данные; обновление сбрасывает несохранённые поля. RU/KZ сохраняет введённые значения и ограничение запуска.

В «Очередь» доступны фильтры источника, типа и состояния, страницы истории, выбранная задача, расписание повтора, безопасная причина ошибки и последние события. «Повторить задачу» доступно для `FAILED`; после действия открывается та же задача без фильтра `FAILED`, чтобы её новое состояние не исчезало из просмотра. Отключённый источник сначала нужно включить. Состояния обновляются кнопкой «Обновить очередь»; постоянного автоматического опроса страницы нет.

Успешный сбор содержит ссылки на новые версии публикаций и скачивание исходного HTML/JSON. Это сетевой ответ, а не скриншот. В карточке публикации отображаются источник, время наблюдения, хеш архива и отдельная ссылка скачивания, разрешённая по существующим правам материала. Если дата публикации отсутствует, список явно показывает неизвестную дату и отдельно день наблюдения. API списка дополнительно возвращает `publicationDateBasis` (`OBSERVED`, `SOURCE_DECLARED`, `MANUAL_DECLARED`) и `observedAt`. Список платформ берётся из доступных пользователю записей; произвольная метка источника также доступна в фильтре.

Окончание анализа не подтверждает связь с ЖК или факторы риска. Для этого нужен аналитик МИО. Сбор настроенного HTML/JSON не означает подключения нативного Instagram/TikTok/Telegram API или обхода закрытого доступа.

## Проверенные границы государственных источников

19 октября 2026 проверены открытые страницы и ответы. Правительственный материал направляет пользователей на [Жилищный портал](https://www.gov.kz/memleket/entities/akimvko/press/news/details/1287143?lang=ru). В описании [получения выписки ДДУ](https://www.gov.kz/services/3910?lang=ru) указан личный кабинет и ЭЦП.

Через новый HTTPS-транспорт получены `https://homeportal.kz` (HTML, перенаправление на `/kz/`) и `https://api.homeportal.kz/api/v1/cities` (JSON с полями `id`, `code`, `name`, `region_id`, `name_kz`, `name_ru`, `name_en`). Открытый клиент портала использует API v1. Запрос `https://api.homeportal.kz/api/v1/objects` без учётных данных вернул HTTP 401. Поэтому подключение списка объектов и проверку разрешений не считаем выполненными; нужен разрешённый доступ и подтверждение формата ответа. Реальные 48 паспортов по-прежнему не предоставлены.

## Дальнейшая работа по бэкенду

Календарь, доступ сотрудников, интерфейсы источников/очереди и [фотофиксация со специалистом](backend-construction.md) реализованы последующими этапами. Остаются нативные адаптеры рекламных платформ, разрешённый доступ к государственным реестрам, полные паспорта реальных 48 ЖК, актуализация календарей по официальным источникам, автоматическое определение готовности по фото, эксплуатационное размещение в РК и реальные каналы доставки материалов после подтверждения МИО. Точные границы проверок — в [журнале](verification.md).
