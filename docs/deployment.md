# Запуск за HTTPS-прокси

Это инструкция для оператора. Публичное развёртывание, сертификат доверенного центра, размещение в РК и обучение сотрудников в рамках локальной проверки не выполнены. Любой публичный запуск требует действующего ADMIN, созданного локально до старта, включая учебный режим. Восстановление описано в [отдельной инструкции](backup-recovery.md).

## Подготовка

Нужен Node.js не ниже 24.19, локальный диск для SQLite, отдельный служебный пользователь и права записи только на каталог базы. Выберите сервер в РК и принадлежащий организации домен. Порт приложения закрывается от внешней сети; открыты только необходимые порты прокси. Не размещайте базу, `.env`, архивы и резервные копии в `public/`.

Для рабочих данных используйте отдельную базу `SAQ_DB_PATH` и `SAQ_DATA_MODE=working`. Перед первым запуском создайте ADMIN локально через `scripts/create-user.mjs` с переменной `SAQ_USER_PASSWORD`; удалите эту переменную из окружения после создания. Не передавайте пароль аргументом командной строки. Скрипт должен использовать тот же `SAQ_DB_PATH`, что и сервер. Рабочая база не запустится без действующего ADMIN. Команды seed/reset для неё не применяются.

## Настройки

```dotenv
HOST=127.0.0.1
PORT=4173
SAQ_DB_PATH=/var/lib/saq/working.sqlite
SAQ_DATA_MODE=working
SAQ_PUBLIC_ORIGIN=https://saq.example.kz
SAQ_TRUSTED_PROXY_IP=127.0.0.1
```

Замените домен и путь. Две последние переменные задаются вместе. Origin принимает только HTTPS и не содержит пути, параметров, фрагмента или учётных данных; адрес прокси — один конкретный IP. Неверная конфигурация останавливает запуск до открытия базы. DNS-имя интерфейса в `HOST` не принимается, кроме `localhost`.

Шаблон [Caddyfile](../ops/Caddyfile.example) рассчитан на Caddy на той же машине, к которому браузеры обращаются напрямую. Он сохраняет исходный Host и **перезаписывает** `X-Real-IP` адресом соединения. Это соответствует [документации reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy) и [описанию remote_host](https://caddyserver.com/docs/caddyfile/concepts). Перед включением оператор проверяет конфигурацию установленной версии Caddy и выдачу доверенного сертификата. Сам Caddy в локальной проверке не запускался.

Приложение принимает публичный Host только от `SAQ_TRUSTED_PROXY_IP`, требует единственный корректный `X-Real-IP` и использует его для ограничения попыток входа. Произвольные `X-Forwarded-For`, `X-Forwarded-Host`, `X-Forwarded-Proto` не меняют доверенный адрес или схему. При нескольких прокси/CDN этот шаблон нужно адаптировать к реальной цепочке; нельзя передавать присланный клиентом `X-Real-IP` как доверенный.

Публичные cookies сеанса имеют `Secure`, `HttpOnly`, `SameSite=Strict`; очистка при выходе/смене пароля также содержит `Secure`. Межсайтовые записи отклоняются по Origin и Sec-Fetch-Site. Прямые небраузерные запросы без Origin всё равно требуют обычной авторизации. Первый ADMIN через публичный HTTP API не создаётся.

## Наблюдение и проверка запуска

Локальный `GET http://127.0.0.1:4173/healthz` доступен службе наблюдения даже в режиме HTTPS-прокси. Возвращается только `{"status":"ok"}` либо 503 с `{"status":"unavailable"}` при недоступной БД. Проверяется доступность SQLite, а не внешних источников, актуальность календаря или успешность последних задач. HEAD не возвращает тело. Подробный `/api/health` остаётся за обычной проверкой доступа.

В публичном режиме добавляется HSTS на год без includeSubDomains. Для страниц действует CSP: свои скрипты/шрифты, изображения из приложения, data URI и плитки OpenStreetMap, запрет встраивания и объектов. Экспорты и сырые архивы могут задавать более строгую собственную CSP. Обычный локальный HTTP не выдаёт HSTS и Secure-cookie. Лимиты соединения: тело запроса 30 с, заголовки 10 с, keep-alive 5 с, до 100 заголовков.

После настройки оператор проверяет доверенный TLS в обычном браузере, вход, права MIO/GASK/LAW/ADMIN, создание/просмотр материалов, скачивание архива и выход. Отдельно проверяются перезапуск службы и сохранность данных. Самоподписанный сертификат и игнорирование ошибок сертификата допустимы только в изолированном QA, для публичного сервера это не результат приёмки.
