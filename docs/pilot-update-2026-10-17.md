# Доработки по присланному ТЗ — 17 октября 2026

Пользователь попросил перейти от ранее выбранных правил хакатонного PDF к присланному техническому заданию пилота. Это изменение требований; исторические сигналы не пересчитаны. Существующие незакоммиченные изменения интерфейса сохранены.

## Что реализовано

| Требование | Реализация и границы |
| --- | --- |
| Веса и объяснение риска | По умолчанию +40/+20/+15/+15/+10/−15; диапазон 0–100; каждый подтверждённый код учитывается один раз. Веса редактируются администратором с новой версией. Гипотезы не начисляют баллы. |
| Условия зон | Непроверенное основание, существенные обстоятельства и ожидающие проверки сведения дают жёлтую. Красная требует подтверждённых R1, R2 и R3 при подтверждённом отсутствии основания. Фактор простоя DELAY влияет на зону без дополнительных баллов. Снижение балла за график не маскирует обстоятельства риска. Это консервативная реализация прототипа; самостоятельного правового решения нет. |
| Готовность | Редактируемые значения 0–100, источники и даты. R5 допускается только при заявленной готовности выше подтверждённой, без произвольного порога 20 п.п. Изменения исходных значений возвращают R5 на проверку. |
| Реестр и паспорт | Новые номера SQ-OBJ-NNNN; добавление объектов демореестра; поля участка, компаний, документов, сроков, связанных сведений и четырёх ручных проверок реестров. Сохранение требует источника и проверяет конфликт редактирования. Пустые поля не заполнены вымышленными подтверждениями. |
| Карта | Подложка OpenStreetMap и метки из координат текущего реестра, цвет зон, фильтры города и заполненного района, переход к объекту. Подложка требует интернета; при ошибке остаются метки и список с координатами. Нет выдуманных координат пилотных 48 ЖК. |
| Реклама и словарь | Ручной текст и URL; редактируемый словарь; приоритетная сортировка по весам формулировок, фильтры источника и объекта. Словарь не выдаётся за результат ML-модели и не начисляет баллы сам по себе. |
| Снимки публикаций | Ручная загрузка PNG/JPEG до 700 КБ, время загрузки и SHA-256. SQLite-триггеры запрещают изменение и удаление сохранённого файла. Ручная отметка удаления источника сохраняет текст и изображения. Это архив загруженного снимка, а не автоматический захват страницы. |
| Сигналы | Новые номера SQ-ГГГГ-NNNN, начальный статус «Требует подтверждения». Красные объекты получают внутренний сигнал автоматически. Неизменившаяся оценка одной версии не создаёт повторные уведомления после архивации. Ручное создание остаётся доступным. |
| Снимок и выгрузка | Новые сигналы сохраняют паспорт, факторы, тексты и загруженные изображения. HTML-выгрузка включает изображения автономно. Пустые разделы показывают отсутствие внесённых сведений; ранее несохранённый исторический контекст не восстанавливается. |
| Маршрут | МИО подтверждает получателя и основание; назначение сохраняется во внутренней очереди. Получатель сохраняет результат однократно. Внешняя передача в органы отсутствует. |
| Срок ответа | Пять рабочих дней после дня назначения; исключаются суббота, воскресенье и настроенные оператором даты SAQ_NON_WORKING_DATES. Просрочка показывается в карточке. Официальный календарь праздников/переносов не подключён. |
| Роли и доступ | После создания первого администратора включается обязательный вход. МИО проверяет и назначает, получатели видят назначенные материалы и вносят ответ, администратор создаёт пользователей и меняет правила. Проверки выполняются на сервере. До создания аккаунтов остаётся явно обозначенный локальный демодоступ. |
| Расписание | Пересчёт сохранённых факторов при запуске и изменениях; устойчивые интервалы 7/30 дней для жёлтой/зелёной зон. Проверка наступления срока — раз в минуту работающего процесса; пропуски догоняются после запуска. Сбор внешней рекламы этот механизм не выполняет. |

## Проверка

- 49 автоматических проверок охватывают направление R5, снижение балла R6, классификацию зон, миграцию, неизменяемость снимков, конфликт редактирования, сохранение изображений и автономный экспорт, дедупликацию сигналов, календарь ответа, версии настроек, расписания и права получателей.
- Браузерный сценарий: вход МИО → паспорт → новый сигнал → назначение ГАСК → выход → вход ГАСК → результат реагирования; отдельно настройки администратора, изменение веса, карта со сменой города, создание нового объекта и загрузка снимка с проверкой его сохранности после отметки удаления источника.
- Казахская версия настроек проверена при ширине 360 пикселей без горизонтального переполнения. Это не полная проверка каждого экрана на всех устройствах.
- Выявленное влияние CSS на атрибут hidden исправлено: скрытые по роли действия исключаются из интерфейса; права API проверяются отдельно тестом.

## Что требует внешних данных или отдельного внедрения

1. Реальные паспорта всех 48 ЖК Усть-Каменогорска и данные районов.
2. Доступы и адаптеры государственных реестров.
3. Автоматический ежедневный сбор всех рекламных источников и захват/архивирование страниц.
4. Фотофиксация и подтверждённая методика измерения готовности.
5. Реальная передача материалов в органы и подтверждение доставки.
6. Официальный календарь рабочих дней, промышленная инфраструктура в РК, требования к персональным данным, восстановление/отзыв доступа и эксплуатационные регламенты.
7. Обучение сотрудников и приёмка по результатам реального пилота.

Работающая локальная версия не означает завершение промышленного пилота.

## Следующий этап: импорт реестра

Добавлен путь «Реестр ЖК → Импорт CSV»: пустой шаблон, выбор UTF-8 файла или вставка текста, обязательные источник и дата, проверка всех строк, предпросмотр и отдельное сохранение пакета. Лимит — 500 объектов и 700 КБ. Поддерживаются `;`/`,`, BOM, кавычки, переносы внутри ячейки и ведущие нули БИН. Ошибка или повтор отклоняют весь пакет; сбой записи откатывает и объекты, и аудит. Повтор определяется по нормализованным БИН, городу, адресу и названию, без нечёткого объединения адресов.

Импортированные поля не становятся подтверждёнными фактами. Сохраняются исходный источник, дата и время загрузки; после последующей ручной правки происхождение импорта остаётся в паспорте. Начальное правовое основание UNKNOWN, балл 0, зона жёлтая.

Режим `working` использует отдельную пустую базу и требует заранее созданного администратора. Встроенное учебное заполнение и сброс запрещены, сервер проверяет соответствие флагов записей режиму. Непустую демобазу нельзя переименовать в рабочую. Интерфейс и печатный экспорт показывают режим корректно; примеры учебных публикаций в рабочей форме скрыты.

Добавлены проверки атомарности, повторов, устаревшего предпросмотра, происхождения данных, запрета сброса рабочей базы и прав HTTP.
