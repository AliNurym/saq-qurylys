# Фотофиксация и история готовности

Реализован серверный процесс приёма и проверки фотоотчётов. Процент готовности и метод его определения вносит специалист. Автоматическое определение процента по изображению, проверка геолокации, времени съёмки и личности фотографа не реализованы.

## Процесс

1. МИО загружает PNG/JPEG, указывает дату наблюдения, процент, источник и метод оценки. Отчёт получает статус `PENDING`; паспорт и баллы не меняются.
2. МИО подтверждает или отклоняет отчёт с обоснованием. При подтверждении требуется отдельное решение `applyToReadiness`: сохранить только в истории наблюдений либо применить как текущую проверенную готовность.
3. Применение требует `expectedUpdatedAt` из свежей карточки. Более старое наблюдение не заменяет более позднее измерение. Исторический отчёт можно подтвердить без применения.
4. Изменение готовности сохраняет неизменяемую запись истории, увеличивает `readinessRevision`, переводит ранее подтверждённый R5 в `UNKNOWN`. Старый R5 нельзя подтвердить на новой версии сведений: требуется новый фактор с новыми основаниями.
5. Новый сигнал сохраняет текущий применённый фотоотчёт вместе с байтами изображения, решением, динамикой и историей готовности. Автономная HTML-выгрузка содержит эту фотографию. Позднее изменение паспорта не меняет снимок сигнала.

Подтверждает и применяет МИО; обязательного второго независимого согласующего нет. Проверенный процент означает сохранённую оценку специалиста, а не установленную системой физическую готовность объекта.

## API

| Метод и путь | Назначение |
|---|---|
| `POST /api/complexes/:id/observations` | Приём: `201` для нового, `200` для точного повтора |
| `GET /api/complexes/:id/observations?limit=50&before=UUID` | Все статусы, страницы по 1–100 записей, `nextCursor` |
| `GET /api/complexes/:id/observations/:observationId` | Метаданные, решение и связь исправления |
| `GET /api/complexes/:id/observations/:observationId/photo` | Исходные байты, MIME и `X-Content-SHA256` |
| `POST /api/complexes/:id/observations/:observationId/review` | Неизменяемое решение с обоснованием |
| `GET /api/complexes/:id/readiness-history?limit=50&afterRevision=0` | История изменений, страницы по 1–200 записей, `nextRevision` |

Загрузка: `observedDate` (`YYYY-MM-DD`, существующая дата не позднее сегодняшней по времени Казахстана), `completionPercentage` (0–100), `source` (3–500 символов), `method` (10–1000), `description` (до 2000), `data` (чистый base64), необязательный `supersedesId`. Дата наблюдения указывается оператором, отдельно от времени загрузки. В поле паспорта дата хранится с техническим временем 12:00 UTC, которое не является временем съёмки.

Решение: `status: CONFIRMED | REJECTED`, `expectedStatus: PENDING`, `reason` (5–1000 символов). Подтверждение требует логического `applyToReadiness`; применение также требует `expectedUpdatedAt`. Повтор идентичного решения идемпотентен и не применяет старую готовность заново. Изменённое решение возвращает `409`; исправление оформляется новым отчётом.

Изображение: до 700 КиБ, 16 миллионов пикселей и 16000 на сторону. PNG проверяется по структуре, CRC, параметрам, распаковке и длинам строк; APNG не принимается. JPEG проверяется по структуре маркеров, размерам, таблицам и наличию сканирования; полного декодирования JPEG-пикселей сервер не выполняет. Это ограниченная проверка формата, не антивирус и не доказательство подлинности. Исходные байты сохраняются без преобразования. Новая загрузка снимков рекламы использует ту же проверку; прежние изображения не переписываются.

## Целостность и доступ

- Фото, сведения загрузки, решение и история защищены от изменения/удаления триггерами SQLite. Ошибка записи аудита отменяет всю операцию.
- SHA-256 позволяет сравнить сохранённые байты с доверенной копией хеша. Он не удостоверяет происхождение изображения и не защищает от администратора, способного переписать всю базу.
- Исправление ссылается на прежнюю запись. Один отчёт не может иметь два подтверждённых исправления. Исправление текущего источника готовности требует явно применить новую оценку. Старые сигналы сохраняют прежнюю фотографию.
- Ручное изменение процента, источника или даты в паспорте снимает ссылку на применённое фото и сохраняет историю. Сохранение неизменённых значений оставляет ссылку.
- Получатели ГАСК/LAW читают фото и историю только назначенных объектов. Администратор может читать; материалы изменяет МИО. В пустой демобазе действует существующий локальный демодоступ.
- Сброс базы запрещён при наличии фотоотчётов или истории готовности.

## Динамика и ограничения

Динамика содержит подтверждённые наблюдения без исправленных предшественников. Если оценки одного дня различаются, все точки этого дня отмечены как конфликтующие, разница с соседней датой не выводится. Снижение оценки сохраняется; оно автоматически не подтверждает простой или R6. Сравнение заявленной и проверенной готовности показывает обе даты: разные даты требуют анализа.

Снимок сигнала включает последние 50 точек динамики и 50 записей истории с общими количествами и признаком ограничения. Фотография сохраняется только для текущего применённого отчёта. Остальные фото остаются в базе и доступны отдельными запросами; полная история доступна страницами API. Изменения до появления истории не восстанавливаются. Старые сигналы без фотофиксации не дополняются текущими изображениями.

## Работа в интерфейсе

Откройте ЖК → «Ход строительства». Сверху отображаются заявленная и проверенная готовность с датами; разные периоды помечены явно. МИО раскрывает «Добавить фотоотчёт», заполняет оценку, источник и метод, выбирает файл и сохраняет для проверки. Смена RU/KZ сохраняет заполненные поля и выбранный файл.

В списке выберите отчёт. Для новой записи доступны три явных решения: подтвердить только отчёт, подтвердить и обновить готовность, отклонить. Обоснование обязательно. Если паспорт изменился, операция возвращает конфликт; кнопка «Обновить сведения» получает свежую версию, сохраняя текст решения. После повторной проверки данных решение можно отправить снова. Исходное изображение открывается нажатием на фото; хеш и идентификатор находятся в раскрываемом разделе целостности.

Исправление создаётся через «Создать исправление с новым фото». Прежняя запись сохраняется, а применённая оценка имеет отдельную отметку. Динамика и история паспорта раскрываются ниже; списки отчётов и история поддерживают переход между страницами. В карточке сигнала отображается сохранённая фотография; HTML-экспорт содержит её автономно. Получатели видят материалы назначенных объектов без форм изменения.

Процесс проверен через сервисы, HTTP и браузер на изолированных базах. Браузерный сценарий включает реальную загрузку синтетического PNG, смену языка с сохранением файла, конфликт версии, обновление сведений, применение оценки, создание сигнала и выгрузку. Исправления, отклонение и пагинация покрыты серверными тестами и проверками шаблонов, но отдельный браузерный проход этих веток не выполнялся. Синтетические изображения проверяют процесс, а не качество реальной оценки строительства.
