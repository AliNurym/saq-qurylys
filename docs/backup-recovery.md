# Резервное копирование и восстановление

Команды используют встроенный `node:sqlite backup`; дополнительные пакеты не нужны. Источник открывается только для чтения, рабочий сервер может продолжать работать в WAL. Копируется согласованный снимок SQLite, включая хранящиеся в базе скриншоты, фото, архивы публикаций, сигналы, календарь и аудит. `.env`, внешние ключи, конфигурация прокси, программа и модели вне базы в копию не входят.

## Создать и проверить

Запускайте из корня проекта с тем же `SAQ_DB_PATH`, что у службы:

```text
node scripts/backup.mjs create /private/saq-backups/2026-10-19-0900
node scripts/backup.mjs verify /private/saq-backups/2026-10-19-0900
```

На Windows используйте свой абсолютный путь, заключая пути с пробелами в кавычки. Создание принимает **новый каталог**, существующий не перезаписывает. Родительские каталоги создаются при необходимости. Источник должен существовать; база в памяти не поддерживается. Запускать с минимальными правами оператора, не через HTTP API.

В результате: `database.sqlite` в самостоятельном режиме DELETE без WAL и `manifest.json`. Манифест записывается последним, содержит размер, SHA-256, режим demo/working, количество строк по таблицам и контрольные суммы защищённых материалов. После прерывания может остаться незавершённый каталог; проверка не считает его готовой копией. Удалять такой каталог оператору следует только после проверки пути и наличия других рабочих копий.

Проверка повторно сверяет размер/хеш, `integrity_check`, внешние ключи, состав таблиц и материалы. Неожиданные `-wal`, `-shm`, `-journal`, ссылки вместо файлов, изменённый манифест и выход имени файла за каталог отклоняются. SHA-256 выявляет повреждение и несоответствие; это **не подпись** и не подтверждение подлинности копии от неизвестного отправителя.

## Восстановить в новый файл

```text
node scripts/backup.mjs restore /private/saq-backups/2026-10-19-0900 /var/lib/saq/recovered-2026-10-19.sqlite
```

Операция не заменяет существующую базу. Целевой файл и его SQLite-файлы `-wal`, `-shm`, `-journal` должны отсутствовать. Каталоги под `public/` запрещены, включая переход через junction. Копия сначала проверяется и мигрируется во временном файле; защищённые снимки сигналов, архивы, скриншоты, строительные наблюдения/решения/история и версии календаря сверяются по исходным колонкам. Новый файл появляется только после успешной проверки.

Для публикации используется жёсткая ссылка в том же каталоге, которая не заменит появившийся параллельно файл. Нужна локальная файловая система с поддержкой hard link, например NTFS/ext4. Сетевые папки и файловые системы без этой возможности не поддерживаются этим сценарием. Файлы синхронизируются перед завершением; устойчивость к внезапному отключению питания на конкретном диске/ОС отдельно не измерялась.

### Доступ после восстановления

Восстановление записывает `DATABASE_RESTORED` от `Local recovery` с хешем копии и числом изменённых записей. При этом:

- Все сеансы удаляются, старые cookies перестают работать.
- Все восстановленные аккаунты отключаются и требуют смены пароля. Авторы и роли сохраняются в истории.
- Все источники отключаются; ожидающие и выполняемые задачи получают CANCELLED/RESTORE_CANCELLED, аренды сбрасываются. Успешные задачи и архивы сохраняются.
- Старые счётчики неудачных входов очищаются.

Это предотвращает автоматическое возвращение доступа и запуск устаревшей очереди из старой копии. Сначала создайте **новый** ADMIN локальным `scripts/create-user.mjs` с новым именем и свежим паролем, направив `SAQ_DB_PATH` на восстановленный файл. Рабочая база и любой публичный HTTPS-запуск без действующего ADMIN запрещены. Проверьте сотрудников; перед включением старого аккаунта сбросьте пароль. Проверьте настройки и доступность источников, затем включайте нужные источники вручную. Старые активные задания не возобновляются.

Для переключения остановите старую службу, сохраните её базу отдельно и измените `SAQ_DB_PATH` на новый файл. Не копируйте файл поверх работающей SQLite. После запуска проверьте health, вход, права, выборочные сигналы/фото/архивы и аудит. Старую базу сохраняйте до приёмки восстановления; это ручная операция оператора.

## Хранение и границы проверки

Копии содержат персональные данные, хеши паролей и материалы. Нужны отдельные ACL/права ОС, защищённый носитель и политика сроков хранения. Файлы создаются с 0600, каталог с 0700 там, где ОС поддерживает POSIX-права; в Windows оператор проверяет ACL. Шифрование и цифровая подпись в этой команде не реализованы. Рекомендуемый каталог `backups/` исключён из Git, однако это не замена защите носителя.

Расписание и ротация не включены автоматически. Частота, отдельная копия вне основного диска и периодическая репетиция восстановления определяются оператором. Допустимая потеря данных и время восстановления на промышленных объёмах не измерялись. Локальные проверки используют изолированные БД и подтверждают сохранность байтов и отказ от перезаписи, а не готовность реального сервера в РК.
