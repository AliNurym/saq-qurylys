# SAQ QURYLYS

Локальный MVP для evidence-first мониторинга объявлений о строящемся жилье. Аналитик сохраняет текст публикации, просматривает извлечённые факты и варианты связи с объектом, подтверждает совпадение и отдельно проверяет каждую гипотезу риска. Результат оформляется как неизменяемый снимок сигнала с историей действий.

Все встроенные компании, объекты, публикации, источники и документы вымышлены. Приложение не подключается к государственным реестрам, не устанавливает юридическую правомерность и не выдаёт сигнал как доказанный вывод о реальной компании.

## Быстрый запуск

Требуется Node.js 24.19 или новее с поддержкой `node:sqlite`.

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
node scripts/setup.mjs
node src/server.mjs
```

Откройте <http://127.0.0.1:4173>. Сервер использует локальную SQLite базу в `data/saq-qurylys.sqlite`. По умолчанию `AI_PROVIDER=local-ml`: локальная обученная модель работает без интернета и ключа. `AI_PROVIDER=rule-based` включает прежний режим только с правилами; `AI_PROVIDER=openai` с ключом включает внешний адаптер. Настройки можно переопределить через `.env`.

## Эксплуатация

Для настроенных HTML-источников добавлен [автоматический статический снимок](docs/page-capture.md): отдельный Playwright/Chromium, связь с исходным архивом и доказательство в сигнале/экспорте. JavaScript и внешние сетевые ресурсы отключены; такие страницы получают отметку PARTIAL. Без настройки браузера сбор сохраняет только исходный ответ и показывает NOT_CONFIGURED.

Для публичного HTTPS-запуска добавлены фиксированный origin, доверенный IP прокси, защищённые cookies, проверки Host/Origin и `/healthz`. До старта нужен действующий ADMIN. Инструкция и пример Caddy: [развёртывание](docs/deployment.md).

Для согласованных копий работающей SQLite и проверенного восстановления в новый файл: [резервное копирование](docs/backup-recovery.md). Восстановление отключает старые аккаунты/источники, отменяет активные задачи и удаляет сеансы; затем оператор создаёт нового ADMIN и проверяет доступ. Реальное размещение в РК и внешние интеграции не выполнены.

Последний полный `node --test` до выравнивания под хакатонный кейс: **301/301 тест** (20 октября 2026). После смены модели баллов build и lint прошли для 109 JS-файлов; тесты после этих изменений не запускались. Ранее проверенные браузерные сценарии и границы приведены в [протоколе](docs/verification.md). Текущие требования хакатона — в [сверке](docs/specification-compliance.md); промышленная готовность DOCX отдельно ограничена в [анализе ТЗ](docs/tz-gap-analysis-2026-10-20.md).

## Разработка и проверки

```powershell
npm run build
npm run lint
npm test
npm run db:seed
npm run db:reset
```

Внешние npm-пакеты не нужны. Если `npm` недоступен, эквивалентные команды — `node scripts/setup.mjs`, `node src/server.mjs`, `node scripts/build.mjs`, `node scripts/lint.mjs`, `node --test`, `node scripts/seed.mjs` и `node scripts/reset.mjs`. `reset` очищает и заново заполняет только демонстрационную базу внутри каталога `data`; для рабочей базы сброс и загрузка учебных записей запрещены. `build` проверяет структуру приложения и синтаксис JavaScript; отдельной компиляции бандла нет, так как интерфейс не использует сборщик.

## Основные разделы

- **Обзор и реестр** — зона риска, правовой статус, источники, новые публикации и гипотезы.
- **Карточка ЖК** — исходные показатели, подтверждённые факторы, правовая проверка, реклама, обращения, история и аудит.
- **Анализ объявления** — исходный текст, сумма/предложение оплаты, точные цитаты, варианты объекта и связанные публикации.
- **Сигнал** — снимок оценки, реквизитов ЖК, исходных текстов публикаций и статусов факторов; очередь проверки, возврат с причиной, архив, аудит и печатное представление.

Интерфейс содержит переключение русского/казахского текста и локальные демо-записи. Аналитик вручную сохраняет текст, ссылку и снимки PNG/JPEG до 700 КБ. Снимки хранятся в SQLite с временем фиксации и SHA-256; изменение и удаление сохранённых файлов запрещены триггерами. Ручная форма не загружает введённый URL; автоматическая загрузка работает отдельно для настроенных администратором источников.

## Автоматический сбор и очередь задач

Бэкенд поддерживает настроенные HTTPS-страницы `HTML_PAGE` и ленты `JSON_FEED`. Источники опрашиваются по сохраняемому расписанию, исходные HTML/JSON архивируются с SHA-256, а анализ запускается отдельной задачей. Очередь восстанавливает работу после остановки, повторяет неудачные задачи с задержкой и не создаёт одинаковую версию публикации дважды. Изменённые публикации сохраняются отдельно; связь с ЖК и подтверждение факторов остаются действиями аналитика.

Управление: «Настройки → Источники» и «Очередь». Новый источник отключён до явного включения. Доступны сохранение с проверкой версии, ручной запуск, фильтры и страницы задач, безопасные причины сбоев, повтор и скачивание исходного HTML/JSON. Токен задаётся на сервере через именованную переменную; его значение не вводится в форму. В карточке публикации доступны архив и время наблюдения. Название платформы не подключает её нативный API. [Контракт и ограничения](docs/backend-collection.md).

Управление доступно администратору через `/api/admin/sources` и `/api/admin/jobs`. Настоящие токены задаются переменными окружения, а конфигурация содержит только их имена. До настройки источников внешние запросы не выполняются. База со сбором источников защищена от демонстрационного сброса и смены режима.

Контракт, маршруты API, ограничения транспорта, восстановление очереди и проверенные границы официальных источников: [Автоматический сбор публикаций](docs/backend-collection.md). Нативные API соцсетей и доступ к закрытому списку объектов Жилищного портала требуют отдельного подключения. HTML-архив не заменяет снимок страницы.

## Риск-правила

- Отсутствие правового основания остаётся `UNKNOWN`, пока аналитик не сохранит источник и конкретное доказательство. Только явный `CONFIRMED_ABSENT` позволяет учитывать R1.
- В балл входят только факторы со статусом `CONFIRMED`. `AI_HYPOTHESIS`, `UNKNOWN` и `REJECTED` дают ноль.
- Каждый код R1–R6 начисляется один раз. Повторные доказательства сохраняются, но не увеличивают вес фактора.
- Базовая модель кейса Codemasters 8.0: R1 +35, R2 +25, R3 +10, R4 +15, R5 +10, R6 +5. R5 требует разницы заявленной и подтверждённой готовности не менее 20 п.п., с источниками и датами; R6 — подтверждённый простой или значимую просрочку.
- В балл входят только подтверждённые факторы. Неизвестное основание и гипотезы дают 0 и отдельно требуют проверки. Зоны: 0–24 зелёная, 25–59 жёлтая; при 60+ зона красная только если одновременно подтверждены R1 и R2, иначе остаётся жёлтой. Балл ограничен диапазоном 0–100.
- Каждый код учитывается один раз, новые сигналы сохраняют источники и версию оценки. Администратор может менять словарь формулировок, который управляет сортировкой объявлений, но не начисляет баллы риска.
- AI-анализ извлекает цитаты и предлагает гипотезы; аналитик подтверждает связь публикации с объектом и каждый фактор отдельно.

Существующая база обновляется без сброса. Сигналы прежней версии без полного снимка контекста явно помечены как исторические: старые тексты публикаций не подменяются текущими. Переключение языка сохраняется в браузере; основные подписи доступны на RU/KZ, тексты вымышленных источников остаются на языке ввода.

## Доработки по ТЗ — 17 октября 2026

- Карта объектов на OpenStreetMap с фильтрами города и заполненного района, цветом зоны и переходом к ЖК. Подложка требует интернета; используется только текущий вид карты, без скачивания областей для офлайн-работы. [Условия использования тайлов](https://operations.osmfoundation.org/policies/tiles/).
- Добавление объектов демореестра с номерами `SQ-OBJ-NNNN`. Паспорт: участок, документы, сроки, компания, связанные сведения, результаты ручных проверок реестров и показатели готовности с источниками. Незаполненные данные остаются явно неизвестными.
- Красные объекты автоматически получают сигнал `SQ-ГГГГ-NNNN` со статусом «Требует подтверждения». Старые номера сохраняются. Снимок новых сигналов включает паспорт, публикации и загруженные изображения; печатный HTML содержит изображения автономно.
- МИО подтверждает внутреннее назначение получателя и основание. Получатель сохраняет результат. Срок — пять рабочих дней после дня назначения. В «Настройки → Рабочие дни» администратор проверяет черновик и публикует календарь с источником, периодом, праздничными датами и рабочими переносами. Редактирование сбрасывает проверку; история доступна страницами. Версия фиксируется в назначении и не меняет прежние сроки после новой публикации. До настройки действует обозначенный резервный режим выходных и `SAQ_NON_WORKING_DATES`. [Контракт календаря и доступа](docs/backend-access-calendar.md).
- Пересчёт сохранённых факторов выполняется при запуске, изменениях данных и по устойчивому расписанию 7/30 дней. Просроченные задания догоняются при запуске. Процесс должен работать; новые внешние источники этот механизм не собирает.
- Роли: МИО проверяет и назначает, ГАСК/правоохранительный орган видят назначенные материалы и вносят ответ, администратор управляет правилами и создаёт учётные записи. Сервер проверяет права независимо от интерфейса.

### Включение входа

Пока учётных записей нет, приложение сохраняет локальный демодоступ. Откройте «Настройки» и создайте первого администратора. После этого демодоступ отключается и требуется вход. Затем администратор создаёт пользователей МИО и получателей. Вход хранится в HttpOnly/SameSite cookie на 8 часов, пароли — в виде scrypt-хешей. В приложении нет готовых паролей.

Для первоначального создания аккаунта через терминал: задайте `SAQ_USER_PASSWORD` в текущем процессе PowerShell и выполните `node scripts/create-user.mjs USERNAME ADMIN`; после выполнения удалите эту переменную. Не сохраняйте пароль в исходниках или командных файлах. В «Настройки → Сотрудники» доступны отключение/включение, смена роли, отзыв сеансов и выдача временного пароля. Новые сотрудники из интерфейса обязаны задать личный пароль до работы с материалами. Для обычной смены своего пароля откройте «Учётная запись»; после смены нужен повторный вход. [Маршруты и ограничения](docs/backend-access-calendar.md). Промышленное размещение, HTTPS, корпоративная идентификация и требования к персональным данным требуют отдельной подготовки.

### Демо-профиль для хакатона

Обычный `node scripts/setup.mjs` создаёт **10 синтетических ЖК и 16 объявлений**, что превышает минимум кейса 8/12. Встроенные имена, паспорта, источники, оценки и решения вымышлены и не являются сведениями госорганов или результатом реального пилота.

Для отдельного сценария пилотного брифа можно включить `SAQ_PILOT_48=1`; этот дополнительный набор тоже полностью синтетический, не обязателен для кейса и не закрывает требования DOCX к 48 реальным паспортам.

Приложение также содержит карту, реестр, мониторинг публикаций, объяснимые факторы риска, роли, журнал действий и русский/казахский интерфейс. Настроенные HTML-источники могут сохранять снимок страницы в заданных пределах; закрытые гос API для хакатона не обязательны. Точность учебной модели на реальных данных не измерена.

### Импорт и отдельная рабочая база

В разделе «Реестр ЖК → Импорт CSV» скачайте пустой шаблон. Загрузите UTF-8 CSV (до 700 КБ, 1–500 объектов, разделитель `;` или `,`) или вставьте его текст, укажите источник и его дату. Сначала выполняется проверка всех строк, затем отдельной кнопкой сохраняется весь пакет. При ошибке или повторе пакет отклоняется целиком; существующие карточки не перезаписываются. Если после предпросмотра изменились файл, источник или состав реестра, проверку нужно повторить.

Обязательные столбцы: `name`, `city`, `address`, `developerName`, `developerBin`, `latitude`, `longitude`. БИН должен оставаться текстом из 12 цифр, включая ведущие нули; координаты задаются с десятичной точкой. Остальные столбцы из шаблона заполняют поля паспорта. Повтор определяется по нормализованным БИН, городу, адресу и названию ЖК; это точная проверка, а не нечёткое сопоставление разных написаний адресов. Источник, дата и время импорта сохраняются в паспорте и журнале. Импорт не подтверждает ни правовое основание, ни результаты сверки реестров: начальное основание — `UNKNOWN`, балл — 0, профиль рискового балла — зелёный с отдельным признаком «нужна проверка». Зелёная зона не означает, что объект проверен.

В демонстрационном режиме все добавления остаются учебными. Для реальных сведений используйте отдельный путь и режим `working` в `.env` или переменных процесса:

```powershell
$env:SAQ_DB_PATH = './data/saq-working.sqlite'
$env:SAQ_DATA_MODE = 'working'
$env:SAQ_USER_PASSWORD = [System.Net.NetworkCredential]::new('', (Read-Host 'Пароль первого администратора (от 12 символов)' -AsSecureString)).Password
try { node scripts/create-user.mjs saq.admin ADMIN } finally { Remove-Item Env:SAQ_USER_PASSWORD }
node src/server.mjs
```

Рабочий сервер требует заранее созданного администратора. После входа администратор создаёт аккаунт МИО для импорта и проверки данных. Учебное заполнение не выполняется, режим хранится в базе; переключение непустой базы запрещено. Рабочий режим отделяет данные, но сам по себе не означает промышленную готовность или подтверждение достоверности сведений. Существующая демобаза не изменяется этой инструкцией.
